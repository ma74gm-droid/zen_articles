# はじめに

F2-423でZigbee通信を行うためにSonoff ZBDongle-Eを接続しましたが、デバイスが認識されませんでした。

調べたところ、別途ドライバをインストールする必要がありました。
セットアップ方法と動作確認の手順を記録します。

---

## 環境構成

### TerraMaster F2-423
- OS: TOS 6.0.770
- パッケージ（.tpk）: [KernelModules](https://tmnascommunity.eu/download/kernelmodules/)

### Sonoff ZBDongle-E

## 手順

### 1. KernelModules のダウンロード

「KernelModules TOS6 6.X.XXX.X x86_64.tpk」を選択し、.tpkファイルをダウンロードします。

パッケージには複数のドライバが含まれています。ZBDongle-Eでは`cp210x`と`usbserial`を使用するため、両方を有効にします。`usbserial`は`cp210x`が使用するモジュールです。

### 2. App Centerからのインストール

1. App Centerでダウンロードしたファイルを指定し、手動インストールを実行します。
   > App Center > Settings > Install Application Manually

2. インストール済みアプリの一覧にKernelModulesが表示されることを確認します。
   > App Center > Settings > Installed

### 3. KernelModulesの設定

デフォルトではすべてのドライバが無効です。使用するドライバの行のコメントを外し、設定を適用します。

> KernelModules > Configuration Files > Edit drivers to load

```conf
####uncomment the driver you want to load####
####start of driver list##################
####usbserial module is required for most of the drivers, make sure you enable it !!!####
usbserial.ko
####class drivers####
#usblp.ko
#cdc_acm.ko
####usb serial drivers####
cp210x.ko
```

### 4. ログの確認

設定を適用してNASを再起動すると、起動時にドライバが自動で読み込まれます。KernelModulesのログに次のような出力があることを確認します。

```text
YY/MM/DD 10:45:11 copy usbserial.ko to kernel module folder
YY/MM/DD 10:45:11 copy cp210x.ko to kernel module folder
YY/MM/DD 10:45:13 loading kernel module usbserial
YY/MM/DD 10:45:13 usbserial driver is loaded
YY/MM/DD 10:45:13 loading kernel module cp210x
YY/MM/DD 10:45:13 cp210x driver is loaded
```

### 5. デバイスの動作確認

Sonoff ZBDongle-Eを接続し、デバイスが認識されることを確認します。SSH接続を有効にし、必要に応じて以下のコマンドで状態を確認してください。

#### 読み込まれているモジュール

```bash
lsmod
```

出力例:

```text
Module                  Size  Used by
cp210x                 28672  1
usbserial              45056  3 cp210x
```

#### 認識されているUSBデバイス

```bash
lsusb
```

出力例:

```text
Bus 001 Device 002: ID 10c4:ea60 Cygnal Integrated Products, Inc. CP2102/CP2109 UART Bridge Controller [CP210x family]
```

#### シリアルポートのパス

`/dev/ttyUSB0`のようなデバイスファイルが作成されていることを確認します。番号は環境によって異なる場合があります。次のコマンドでは、デバイスを識別しやすい`/dev/serial/by-id/`のパスも確認できます。

```bash
ls -l /dev/serial/by-id
```

出力例:

```text
total 0
lrwxrwxrwx 1 root root 13 May 16 15:06 usb-Itead_Sonoff_Zigbee_3.0_USB_Dongle_Plus_V2_b6e070d8ffa0f011aab02881bb936ffa-if00-port0 -> ../../ttyUSB0
```

#### サービスの状態

`systemctl status`でKernelModulesのサービス状態を確認できます。出力例では、systemdが`/etc/init.d/KernelModules`を呼び出しており、サービスは`active (running)`です。

```bash
systemctl status KernelModules.service
```

出力例:

```text

     Loaded: loaded (/etc/init.d/KernelModules; generated)
```

## 補足

### App Centerのアプリインストール先

アプリごとのディレクトリは、以下のパスに作成されます。
> **/Volume1/@apps/**

### 設定ファイルの改行コードがCRLFの場合にサービスが起動しない

私の環境では、改行コードが原因でサービス起動スクリプト（bash）がエラー終了していました。
改行コードをLFに変更して保存すると、問題が解消しました。

```text
/Volume1/@apps/KernelModules/bin/kernelmodules.conf
```
